# BLK-014 — Bandeau d'actualités reste saccadé malgré 3 approches

| Friction                                                                                                                        | Cause réelle                                                                                                                                                                                                                                                                                                                                                                                                                                     | Solution                                                                                                                                                                                                                                                       | Statut |
| ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Le défilement du bandeau d'actualités sature à ~5fps (80%+ de frames "janky", mesuré via `dumpsys gfxinfo`) sur la TV TCL cible | Inconnue à ce stade — ni la réduction du nombre d'items affichés (86%→80% de jank, différence négligeable), ni les hints GPU (`will-change`, `translate3d`, `setLayerType(HARDWARE)` côté Android), ni un rendu vidéo H.264 généré côté serveur (supposé profiter du même chemin matériel qu'un autre écran de veille vidéo fluide — Aerial View — sur la même TV) n'ont amélioré la situation ; la vidéo s'est même révélée pire selon Baptiste | Aucune pour l'instant — mis de côté à la demande de Baptiste pour investiguer dans une session future ; le pipeline vidéo (ffmpeg + endpoint `/api/news-ticker.mp4`) a été intégralement annulé, retour au bandeau CSS/DOM d'origine (moins pire que la vidéo) | ouvert |
