# LRN-005 — Un `JAVA_HOME` système obsolète casse Gradle/AGP avec une erreur trompeuse

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                             | Contexte                                                                                                                        | Application future                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `gradle assembleDebug` échouait avec une erreur de "no matching variant" / résolution de dépendances sur `com.android.tools.build:gradle:8.6.0`, qui ne mentionne jamais explicitement "mauvaise version de Java". La cause réelle : la variable d'environnement `JAVA_HOME` système pointait vers un JDK 8 alors que `java` sur le PATH résolvait vers un JDK 17 — Gradle priorise `JAVA_HOME` sur le PATH | Premier build en ligne de commande du projet Android (`android-app`), sur un PC où plusieurs JDK sont installés (8, 11, 14, 17) | Si Gradle échoue sur une résolution de dépendance/variant "Java X vs Java Y" sans rapport apparent avec le code, vérifier `JAVA_HOME` en premier (`echo $JAVA_HOME`) avant de creuser côté `build.gradle.kts`/versions de plugin — le forcer explicitement dans le script de build plutôt que de dépendre de l'environnement système |
