# LRN-010 — Canvas WebGL (ogl) sous `transform: scale()` : double réduction de taille + peinture figée sur uniform stale

## Pattern observé

En intégrant le composant `Grainient` (fond dégradé animé, `rpi-app/src/components/Grainient.tsx`) dans le canvas de l'éditeur — qui vit sous un `transform: scale(s)` (voir [LRN-002](LRN-002.md), [LRN-008](LRN-008.md)) — deux bugs silencieux sont apparus :

1. **Double scale du canvas** : `ogl`'s `Renderer.setSize(w, h)` fait `canvas.style.width = w+'px'` en interne, où `w` vient de `container.getBoundingClientRect()` — qui renvoie déjà la taille **affichée** (post-`transform:scale`). Le canvas hérite ensuite lui-même du `transform:scale` de son ancêtre → la taille est réduite deux fois. Résultat : le rendu WebGL n'occupe qu'un coin du conteneur au lieu de le remplir.
2. **Peinture figée** : changer les props de couleur (donc les uniforms) ne suffit pas à repeindre si la boucle `requestAnimationFrame` est en pause (onglet masqué, conteneur hors du viewport via `IntersectionObserver`). Les uniforms sont à jour mais le dernier frame rendu reste affiché jusqu'à la reprise de la boucle.

## Pourquoi

`ogl` (comme beaucoup de libs WebGL légères) suppose un usage "plein cadre" simple, sans ancêtre transformé en CSS. Le pattern économie de perf (pause du RAF hors champ / onglet masqué) est correct pour l'animation continue, mais casse l'hypothèse implicite "un changement de prop se voit au prochain repaint".

## Comment appliquer

Pour tout composant WebGL (ogl, three.js, etc.) monté à l'intérieur d'un conteneur affecté par un `transform: scale()` :

- Après chaque appel à `renderer.setSize()`, ré-imposer `canvas.style.width/height = '100%'` pour que le canvas suive la taille CSS de son propre conteneur plutôt que le pixel size déjà scalé renvoyé par `setSize`.
- Dans l'effet qui synchronise les props → uniforms, forcer un `renderer.render({ scene: mesh })` immédiat après la mise à jour, sans dépendre de la boucle RAF pour repeindre.
