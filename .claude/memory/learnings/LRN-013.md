# LRN-013 — Tester un `Radix Tabs.Trigger` par script exige la séquence pointer/mouse complète

| Pattern observé                                                                                                                                                                                                                 | Contexte                                                                                                                                                        | Application future                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Un `.click()` JS synthétique sur un `Radix Tabs.Trigger` ne change pas l'onglet actif — Radix a besoin de la séquence complète `pointerdown` → `mousedown` → `pointerup` → `mouseup` → `click` avec `clientX/clientY` cohérents | Vérification automatisée des onglets Widget/Fond de `rpi-app` dans le Browser pane — un vrai clic outil (CDP) fonctionne, un `.click()` dispatché à la main non | Pour tester par script un composant Radix récalcitrant à `.click()`, dispatcher manuellement toute la séquence d'événements pointer + mouse avec les mêmes coordonnées plutôt que de conclure trop vite à un bug produit |
