# LRN-023 — Un setTimeout imbriqué dans un setInterval doit être nettoyé séparément

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                             | Contexte                                                                                                                                                                                                                                                                       | Application future                                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| Un timer créé À L'INTÉRIEUR du callback d'un autre timer (ex: un `setTimeout` dans le callback périodique d'un `setInterval`) n'est pas couvert par le `clearInterval` seul — sa référence doit être stockée dans une variable de portée effet et explicitement `clearTimeout`ée dans le cleanup, sinon il peut se déclencher après démontage/changement de dépendances et provoquer un state update périmé | Détecté par react-doctor (`effect-needs-cleanup`) sur `NewsTickerWidget.tsx` : un fade en 2 temps (`setInterval` + `setTimeout` imbriqué) pouvait laisser un timeout fantôme se déclencher après un rechargement de flux RSS, avec un risque de crash sur un index hors bornes | Vérifier systématiquement dès qu'un effet combine `setInterval` + `setTimeout` (animation en 2 temps, debounce imbriqué, etc.) |
